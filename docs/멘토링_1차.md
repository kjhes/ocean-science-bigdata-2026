# 1차 멘토링 기록 — 방향 전환

> 2026-09-10. 이 문서가 현재 프로젝트 방향의 기준이다.

---

## 1. 지적받은 내용

### ① 장기 예측은 불가능하다

수온에 영향을 주는 요소가 너무 많다 — 기온, 일사량, 다른 해역의 해수 유입,
바람, 자연재해 등. **국내 어떤 모델로도 5년 뒤 수온은 예측할 수 없다.**
우리 팀의 역량 문제가 아니라 문제 자체가 성립하지 않는다.

### ② 숨은 전제가 틀렸다

"같은 지역, 같은 시기면 다른 연도라도 환경이 비슷하다"는 전제 위에
평년값 + 상승률 방식을 세웠는데, 그 전제가 성립하지 않는다.
→ `docs/평년값_전제_검증.md`

### ③ 단기 예측으로 전환하라

먼 미래 대신 **최근 데이터로 앞으로 며칠간의 수온 변화**를 예측한다.

### ④ 산출물은 앱으로

- 양식장 **위치별** + 사육 **어종별** 맞춤
- **고수온 경보 3단계**
- 단계별 **구체적 대응 방법** 제시
- 경보 기준 온도는 **실제로 존재하므로 지어낼 필요가 없다**

### ⑤ 변수를 늘려라

수온 하나만으로는 정확도가 나오지 않는다. 추가할 것:

| 변수 | 역할 |
|---|---|
| 기온 | 표층 수온의 직접 구동 요인 |
| 일사량 | 표층 가열량 |
| 강수량 | 염분 농도 변화 |
| 해풍 | 연직 혼합, 표층 열 분산 |

### ⑥ 기존 해양 예측 모델을 참고하라

## 2. 용어 정정 — RAMS 아니고 ROMS

멘토링 중 "RAMS"로 들었으나 RAMS는 대기 모델이다.
해양 쪽은 **ROMS (Regional Ocean Modeling System)** 이다.

| 출처 | 제공 내용 | 접근 |
|---|---|---|
| 국립해양조사원 ROMS 수치예측모델 | 예측일·예측시간·위경도·표층 수온·유향유속 | 공공데이터포털 OpenAPI, 무료 |
| 바다누리 해양정보 서비스 | 황동중국해 ROMS 격자별 일일 예측 (수온 평균/최대/최소, 염분) | 웹 |
| 국립수산과학원 동해 냉수대 예측시스템 | ROMS + WRF 결합, 실시간 관측으로 오차 보정 | 논문 |

- **남해안은 황동중국해 ROMS 격자에 포함된다.**
- **성능 벤치마크**: 동해 냉수대 예측시스템의 3일 예측 RMSE **0.73℃**.
  조건이 달라 직접 비교는 아니지만 목표 수준의 기준으로 삼는다.

## 3. 프로젝트 성격 변화

| | 이전 | 이후 |
|---|---|---|
| 목표 | 미래 수온 예측 | **고수온 조기경보** |
| 예측 기간 | 1~5년 | **1~7일** |
| 모델 입력 | 날짜 | **환경 실측값** |
| 산출물 | 어종 추천표 | **앱** |
| 어종 자료 역할 | 추천 대상 | **경보 기준값** |
| 검증 가능성 | 불가능 | **가능** |

검증이 가능해진 것이 가장 큰 변화다. 실용성도 함께 올라간다.

## 4. 살리는 것 / 버리는 것

**버림**

- 5년 뒤 예측
- 연도별 상승률 보정(델타 기법)
- 1년 통짜 예측 프레임
- 주 지표로서의 연간 RMSE

**살림**

- 데이터 로딩·전처리 파이프라인 전부
- 결측·중복 처리 규칙
- 어종별 적정·치사수온 표 → 경보 기준으로 역할 변경
- 평년값 모델 → **Baseline으로 유지.** 새 모델이 이겨야 함
- 2024년 9월 분석 → **문제의식의 근거**로 발표에 그대로 사용

**추가**

- 기상 4종 (기온·일사량·강수량·해풍)
- ROMS 예측값
- 앱 (경보 3단계 + 대응 방법)

## 5. 발표 스토리라인

시행착오를 감추지 않고 연구 과정으로 제시한다.

1. 모델을 만들었다 → 성능은 나쁘지 않았다 (Baseline 대비 27~34% 개선)
2. 그런데 2024년만 크게 틀렸다
3. 원인을 분해했다 → 9월 편차 +2.48℃, 여름이 한 달 늦게 끝났다
4. 왜 못 잡았나 → **모델에 숨은 전제가 있었다**
5. 전제가 틀렸음을 확인 → **데이터를 늘려도 해결되지 않는 문제**
6. 그래서 **날짜 기반에서 환경 기반으로 모델을 바꿨다**
7. 결과물: 양식 어가가 실제로 쓰는 고수온 경보 앱

## 6. 다음 단계

1. **고수온 경보 공식 기준 확보** — 국립수산과학원 관심·주의보·경보 단계와 온도.
   앱의 뼈대이자 `anomaly_2024.py`의 임계값 교체분
2. **기상 데이터 수집** — 기상청 ASOS/AWS, 완도·여수·통영·남해 4지점,
   2021~2025 일별 기온·일사량·강수량·풍속
3. **ROMS OpenAPI 신청** — 공공데이터포털
4. **단기 예측 문제 정의** — 예측 기간(3일/7일), 입력 길이, 지역별 모델 대 통합 모델
5. **대응 방법 자료 조사** — 국립수산과학원 고수온 대응요령
   (사료 공급 조절, 환수량 증가, 액화산소 공급 등)
6. 어종별 치사수온의 **노출시간 조건** 확인 (현재 표에는 온도만 있음)

## 7. 2차 멘토링에서 물을 것

1. 단기 예측 모델 구조 — 회귀 대 시계열 대 머신러닝 중 어느 쪽이 적절한가
2. 기상 변수는 관측값을 쓰는가, 예보값을 쓰는가 (실사용 시에는 예보값뿐)
3. ROMS 예측값을 입력으로 쓰는 것과, ROMS 출력을 우리 관측으로 보정하는 것 중 어느 쪽인가
4. 경보 3단계 구분 기준을 온도만으로 할 것인가, 지속시간을 포함할 것인가
5. 어류 폐사가 온도×시간 함수라면 **누적 열량(degree-day)** 개념을 도입해야 하는가
6. ENSO를 대신할 대리변수가 있는가
7. 양식방식별 위험도(현재 정량 자료 없음)를 경보 체계에서 어떻게 쓸 것인가
